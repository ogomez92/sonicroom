# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SonicRoom — low-latency browser audio conferencing (voice) with hi-fi stereo music casting. pnpm monorepo:

- `client/` — React 19 + Vite + Tailwind v4 + zustand, using `mediasoup-client` and `socket.io-client`.
- `server/` — Express 5 + socket.io + `mediasoup` (SFU) + `zod`. Runs TypeScript **directly via `tsx`** (no build artifact).
- `electron_client/` — cross-platform (Win/Mac/Linux) Electron **thin client** that bundles `client/dist` and connects to a **configurable remote instance** via a native Settings window. Runs no server and bundles no ffmpeg/yt-dlp (those stay server-side), so it has **zero native deps**. It serves the client over a custom `app://` origin and a preload injects `window.__SONICROOM_CONFIG__` (serverUrl / iceServers / branding); the client reads these through `client/src/lib/runtime-config.ts` and falls back to same-origin + default ICE on the web, so the web build is unchanged. See `electron_client/README.md`. Built with esbuild (`build.mjs`) + electron-builder; `electron` is in `onlyBuiltDependencies`.

**Use pnpm, never npm.** It's a pnpm workspace, and `onlyBuiltDependencies` (in `pnpm-workspace.yaml`) builds esbuild and mediasoup's native worker. Reinstalling/adding deps can purge `node_modules` and drop the prebuilt `mediasoup-worker` binary — if the server then fails with a worker error on startup, run `pnpm install` to rebuild it. Also: `pnpm add` (v11) may write a malformed `allowBuilds:` stub into `pnpm-workspace.yaml` that then breaks every `pnpm` run with `ERR_PNPM_IGNORED_BUILDS` on the deps-status check — **delete that stub** (esbuild/mediasoup are already approved via `onlyBuiltDependencies`).

## Commands

**System binaries** (the server shells out to these — install on the host, on `PATH` or pointed to by `FFMPEG_PATH` / `YTDLP_PATH`):

- **`ffmpeg`** — recording, Icecast streaming, and transcoding URL/stream audio sources to Opus/WebM.
- **`yt-dlp`** — audio extraction for the in-call URL streamer when a link isn't a direct media URL (YouTube/SoundCloud/IPTV pages, via `/api/audio-proxy`). Keep it current — extraction breaks against site changes when stale (`pip install -U yt-dlp` or the official binary; distro packages lag).

```bash
pnpm install                 # workspace install (builds mediasoup worker)
pnpm dev                     # server (tsx watch :3100) + client (vite :5173) together
pnpm dev:server              # server only
pnpm dev:client              # client only — vite proxies /socket.io and /api to :3100
pnpm build                   # builds the CLIENT only -> client/dist (server needs no build)
pnpm start                   # prod: server runs signaling AND serves client/dist statically
pnpm --filter server test    # server tests (node:test via tsx)
pnpm lint                    # eslint (flat config in eslint.config.mjs, whole workspace)
pnpm format                  # prettier --write (printWidth 100; generated/dist ignored)
pnpm format:check            # prettier in CI/check mode
```

Run a single server test file / single test:

```bash
pnpm --filter server exec node --import tsx --test src/recording-util.test.ts
pnpm --filter server exec node --import tsx --test --test-name-pattern="PortAllocator" "src/**/*.test.ts"
pnpm --filter client exec tsc --noEmit     # typecheck the client
pnpm --filter server exec tsc --noEmit     # typecheck the server (it runs untyped via tsx, so this is the only type gate)
```

Only the server has tests (the client has none). They cover the pure helpers (`recording-util.ts`, `chat-util.ts`, `zip-stream.ts`, `streaming-util.ts`, `kick-util.ts`, `audio-sources.ts`) **and** the stateful managers (`recording.ts`, `streaming.ts`): each manager (and the `audio-sources` transcode resolvers) takes injected deps (`RecordingDeps` / `StreamDeps` / an injected `spawn`) so the tests drive it with fakes — a fake `spawn` (no real ffmpeg/yt-dlp), structural mediasoup Router/Transport/Consumer, a fake clock and fake timers — asserting on the args/SDP/ports/lifecycle without launching a process or touching media.

## Architecture

### Hybrid P2P ↔ SFU transport (the core idea)

A room dynamically switches transport based on size and needs. **`decideMode(peerCount, currentMode, forceSfu)` in `server/src/recording-util.ts` is the single, pure source of truth** — both the join and leave handlers in `signaling.ts` re-evaluate through it:

- ≤2 peers → **P2P mesh**: clients connect WebRTC directly; the server only relays signaling (`p2p-signal`). Media never touches the server.
- 3+ peers → **mediasoup SFU**.
- `forceSfu` pins the SFU even with ≤2 peers when the server _must_ see the media: while **recording** (P2P media is invisible to the server), when a **music caster** is present, or when **`?p2p=off`** was set (`shouldForceSfu` in `signaling.ts`).

On transitions the server emits `switch-to-sfu` / `switch-to-p2p`; the client (`useMediasoup.ts`) tears down one transport stack and builds the other. The outgoing audio graph (below) survives the switch — only senders/producers are rebuilt.

### Client audio graph (`client/src/hooks/useMediasoup.ts`)

One module-scoped shared `AudioContext` for the whole session (resumed on first user gesture for iOS).

- **Outgoing**: `mic → micGain → soft limiter → outDest`. The track added to peers / produced to the SFU is **always `outDest`'s stream track**, so tracks are never swapped on senders/producer across mode switches or when sharing audio. Shared system/tab audio (`getDisplayMedia`) is mixed **straight into `outDest`**, bypassing the mic gain/limiter so music keeps its dynamics.
- **Incoming**: per-peer `MediaStreamSource → gainNode → destination`. `effectiveGain(peerId)` composes per-peer volume × deafen × music ducking; every place that changes gain ramps via `setTargetAtTime`.

### Auto-ducking (controlled client-side)

The server's `AudioLevelObserver` watches **voice producers only** — music/caster producers are deliberately never added to it. It emits `duck {active}` on each on/off transition (`wireDucking` in `signaling.ts`). The **client** does the actual gain ramp: music-peer gain → `volume * DUCK_FACTOR` with `DUCK_ATTACK` (voice starts) / `DUCK_RELEASE` (voice stops) time-constants. Ecobox/the caster just sends raw stereo; ducking timing lives in the client constants, not the caster.

### Music caster (Ecobox)

A send-only "music caster" peer joins with `role: "caster"` (see `joinSchema`). It produces a stereo track but never consumes or sets up P2P, so its presence forces the room onto the SFU. Voice defaults to **mono ~64 kbps** for everyone; it's a **per-user opt-in** to send **stereo ~128 kbps** ("Hi-fi voice" toggle in `DeviceSettings`, persisted as `sonicroom:hifiVoice`, default off — `hifiVoiceEnabled` in the store). The flag is read at **call start** — `forceOpusParams(sdp, hifi)` in `client/src/lib/sdp-munger.ts` sets `stereo`/`maxaveragebitrate` on the P2P fmtp, and the SFU `produce` sets `opusStereo`/`opusMaxAverageBitrate`; `microphoneConstraints` captures 1 vs 2 channels to match. It applies on the **next** call (the live producer's codec can't be re-negotiated mid-call). Why opt-in: most mics are mono (so stereo adds nothing audible) and 128k voice costs **every listener** bandwidth in the SFU fan-out. The router's `maxaveragebitrate: 256000` (`mediasoup-config.ts`) is a **ceiling** above even hi-fi voice — it lets the dedicated stereo caster/share/file producers negotiate full hi-fi — **do not lower it to 64000**, that silently clamps music to voice quality.

### Extra microphones (multi-device streaming)

On top of the single primary voice mic, a user can stream **additional input devices at once**, each as its **own separate producer** (`source: "mic"`) — like `share`/`file` it's a separate track that **forces the room onto the SFU** (`room.extraMicStreamers`, mirroring `sharers`/`fileStreamers`) and is auto-tapped by recording/streaming. Like share/file, it's **reclocked through Web Audio before produce**: `getUserMedia → MediaStreamSource → MediaStreamDestination`, and the **destination's** track is produced (not the raw capture). This is the path that proved **stable against a stereo-drift bug** (a stereo extra mic's two channels sliding apart over time — image walks right + a periodic "boop"). An earlier version produced the **raw** device track and could drift; every _other_ stereo producer (primary voice, share, file) already goes through a dest and was stable, so the extra mic was moved onto a dest too. **The exact mechanism was never pinned down** — it looked browser-specific — so treat the dest route as the empirically-stable choice, not a confirmed fix for a known root cause; don't "simplify" it back to a raw produce without re-testing stereo drift across browsers. The dest's `channelCount` matches the produced layout (mono pick → mono, no dual-mono up-mix). The picker is an accessible checkbox list in `DeviceSettings` (every input device **except** the primary mic and the empty "Default" id, so the same capture can't stream twice), with a **per-device mono/stereo** radio. Persisted as `sonicroom:streamedMicDeviceIds` + `sonicroom:micStereoByDevice` (`streamedMicDeviceIds` / `micStereoByDevice` in the store), carried lobby→call.

- **Client** (`useMediasoup.ts`): `extraMicsRef` (keyed by deviceId) owns each device's `getUserMedia` stream, its `MediaStreamSource`/`MediaStreamDestination` nodes, and its producer (the produced track is the dest's). A **reconcile effect** diffs the store selection against the live producers — **in-call only** (gated on `connected`; the lobby just tracks the baseline, which is applied at join). It starts added devices, stops removed ones, and **re-produces in place** the one whose mono↔stereo flipped (the codec can't renegotiate live, so it re-acquires the capture at the new channelCount and re-produces). All three ops are **serialized through `runExtraMicOp`** so a quick flip-and-back can't overlap on one device (which left a doubled/wrong-channel producer). The flip (`restartOneExtraMic`) produces the **new** producer **before** retiring the old server-side one, so the server still sees a `"mic"` producer for the peer (`hasMoreMics`) and **keeps the SFU pin** — a ≤2-peer room does **not** flap SFU→P2P→SFU. (Genuinely starting the first / stopping the last extra mic still flips a ≤2-peer room SFU↔P2P, as it must — a separate producer needs the SFU.) `produceAllExtraMics` re-produces every selected device in `setupSfuInner` on a mode switch / reconnect; the `extraMic` join flag re-pins SFU first.
- **`extraMicConstraints`** (`lib/microphone.ts`) uses `{ exact: deviceId }` (NOT the voice path's `{ ideal }`) so a busy/unplugged extra mic **fails cleanly instead of aliasing to the default device and doubling audio**, and captures **raw** (no echo-cancel/AGC) like share/file.
- **Incoming tiles** are flagged **`isMicStream`** (a new `PeerState` flag), NOT `isMusic`: a talking mic is **non-votable** (excluded from vote-to-kick — `votableCount` in `Room.tsx` and the kick gates in `ParticipantList.tsx` filter `!isMusic && !isMicStream`) but is **voice-like and NOT ducked** (ducking keys on `isMusic` only). Keyed by producerId (like share/file) and rendered with a Mic icon.
- **Tile detail / producer `title`** (mic **and** share/file): each media producer carries an optional human-readable `title` in `appData` so its tile reads in full — the extra-mic device label (`getUserMedia` track `.label`, e.g. "Virtual Cable 1"), the streamed file's name/URL (`fileStreamName`), or the share's display-capture label ("System Audio"/"Tab audio"). The client stamps it at produce time (`produceOneExtraMic`/`produceFile`/`produceShare`), forwards it on `produce`, and the server (`signaling.ts`) stores it in `appData.title` (zod-validated, trimmed, ≤120 chars) and echoes it on **both** `new-producer` and the join snapshot, so late joiners read the full label at once. `consumeProducer` builds the tile name with the `*_stream_name_titled` message variants (falling back to the bare `*_stream_name` when there's no title), so the SR announcement/aria-label get the detail for free. **File-swap caveat**: the file path reuses one producer across content swaps (no tile churn), so on a swap the client emits **`update-stream-title { producerId, title }`** → the server re-titles the live `appData` + broadcasts **`producer-title-updated`** → consumers relabel via `setPeerName` (looked up through the share/file/mic owner maps). Mics/shares never go stale this way — swapping them makes a fresh producer. The source guard rejects re-titling a `voice`/`music` producer.
- **Mute is voice-only by design**: extra mics keep streaming when you mute (you stop them by unchecking). `producer-pause`/`-resume` already skip non-`voice` sources, and the `AudioLevelObserver` excludes `"mic"`, so extra mics neither pause on mute nor trigger ducking — all correct by construction (no special-casing).
- **Per-producer stop**: unlike `stop-share` (peer-wide, one share per peer), a peer can stream several mics, so `stop-extra-mic { producerId }` closes **one** (server-side, with an ownership/`source==="mic"` guard — a client-side close doesn't propagate). `producerId` is **optional**: a client that registered intent but never reached SFU (so never produced) sends none, and the server still reconciles `extraMicStreamers` so the SFU pin can't leak. The server drops the peer from the set only once their **last** `"mic"` producer is gone.

### Server-side recording (`server/src/recording.ts` + `recording-util.ts`)

Recording is server-side and forces SFU. Per producer: a mediasoup `PlainTransport` pushes RTP to a local UDP port (`PortAllocator` hands out P/P+1 pairs since ffmpeg also opens an RTCP socket at port+1) where an ffmpeg process captures it to a streamable Ogg/Opus file with `-c:a copy` (no re-encode). The download endpoint (`/api/recordings/:id/download`) spawns a **second** ffmpeg that `amix`es all captures (with `adelay` to align late joiners, `normalize=0`) and streams to HTTP `pipe:1` — captures keep running, never interrupted. Recordings are keyed by a `recordingId` capability token, not room name. `RecordingManager` takes injected `RecordingDeps` so the logic is unit-testable without real ffmpeg/mediasoup.

- **Mutes vs the capture ffmpeg.** ffmpeg's SDP/RTP input exits for good after ~20 s without a single packet (10 s once packets have flowed). A producer paused mid-recording is fine (mediasoup's RTCP keeps the socket alive and the Ogg keeps a timestamp gap), but a producer **already paused when its capture starts** sends nothing at all. That capture used to die in 20 s and the person was silently missing from the whole recording (2026-09-19 incident). So `startRecorder` sets up transport + consumer but only spawns ffmpeg (`launchCapture`) once `consumer.producerPaused` is false, via mediasoup's `producerresume` event. `onCaptureExit` relaunches a capture that ends on its own (a new `-N` segment file if it had already captured media; waits for resume if paused; no instant respawn if it died in under `MIN_RESTART_LIFETIME_MS`).
- **Mute gaps in downloads.** Every renderer that reads the Ogg captures passes `KEEP_TIMESTAMP_GAPS` (`-dts_delta_threshold 1000000`) before its inputs. Without it the ffmpeg CLI treats Ogg as a discontinuous-timestamp format and **cuts every gap over 10 s** before `aresample=async=1` can fill it with silence, so long mutes vanished and tracks drifted out of sync. `recording-render.test.ts` checks this with real ffmpeg.

#### Recording a video room (audio rooms are untouched)

**Audio is audio only.** A recording captures picture only in a **video room**, where video producers exist at all; every code path below branches on "did any recorder capture video?", so an audio room's captures, mix and per-track zip are byte-for-byte what they always were. `ProducerInfo.kind` (`"audio"` default) carries the distinction from `signaling` into `RecordingManager`.

- **Capture.** A `camera`/`screen` producer is consumed the same way, but `buildSdp` emits an `m=video` line (`a=rtpmap:96 VP8/90000`, no channel count — video codec names are case-sensitive, so `sdpParamsFromRtp` does **not** lowercase them) and `buildCaptureArgs(..., "video")` remuxes to **WebM with `-c:v copy`** (VP8's native container — still no re-encode). On resume the consumer gets a `requestKeyFrame()` so the capture opens on a decodable frame. Picture captures are excluded from `getMixInputs` — the Opus mixer never sees a `.webm` — and Icecast streaming stays audio-only everywhere (it's an MP3/Opus feed).
- **Per-track download** (`/api/recordings/:id/tracks`). `pairTracks` (pure, in `recording-util.ts`) folds the captures into one entry per track a person would expect: **a peer's camera carries their own voice** (one MP4 per person), **their screen share carries the share's audio**, and everything else — music casters, streamed files, extra mics, and the voice of anyone who never turned their camera on — stays its own Ogg. A voice track is never emitted twice (a camera cycled off/on pairs only with the first segment), entries are ordered by their **earliest** capture (turning your camera on halfway through doesn't move you down the zip), and a header-only picture capture degrades the entry back to plain audio rather than yielding an MP4 ffmpeg can't open. `buildTrackMp4Args` renders one entry: picture letterboxed into a fixed 1280×720 box (so a mid-call resolution change can't break the encoder), `tpad`-ed with black for the time the camera was off and run out to the shared span, the peer's audio `adelay`/`apad`-ed to match. A silent picture still gets an `anullsrc` stereo track.
- **Whole-call download** (`/api/recordings/:id/download`). `buildVideoMixArgs` renders an **MP4** instead of the Ogg: a generated full-size, full-length **black canvas** (`color=…:d=<span>`) with every picture `overlay`-ed into its `gridLayout` cell (squarest grid; the cell shrinks so the canvas never exceeds 1920 wide; every dimension even for H.264) and the room's whole `amix` on top. `eof_action=pass:repeatlast=0` sends a stopped camera's cell back to black instead of freezing its last frame. `mixByRecordingId` returns `{ proc, container, contentType }` so the endpoint labels the download (`.mp4` vs `.ogg`); the client picks the matching suggested filename from `roomIsVideo`.
- Both renderers re-encode (VP8+Opus in, **H.264 + AAC** out) and write to a pipe, which rules out `+faststart` — they emit a **fragmented MP4** (`+frag_keyframe+empty_moov+default_base_moof`), which streams as it's produced and opens in browsers, VLC and NLEs.
- **Tests.** The argv builders and `pairTracks` are unit-tested like the rest (`recording-util.test.ts`), and `recording.test.ts` drives the manager with a video-capable fake consumer. Argv assertions can't prove a file plays, so **`recording-render.test.ts` runs the real ffmpeg**: it pushes a VP8 fixture over real RTP through our SDP + capture args, then renders both downloads and inspects the results — stream codecs, dimensions, decoded frame count, mean volume, and **sampled RGB pixels** (black before a camera came on, that camera's colour after, each camera in its own grid cell). It skips itself where ffmpeg/ffprobe aren't installed.

### Live Icecast streaming (`server/src/streaming.ts` + `streaming-util.ts`)

`StreamManager` mirrors `RecordingManager` and is **independent of it** — both tap the SFU with their own consumers, so a room can record, stream, both, or neither. It also forces SFU. Per producer it has its own `PlainTransport`+consumer → local UDP port (its own `PortAllocator`, range **51000–51998**, distinct from recording's). One **live mixer ffmpeg per room** reads every active producer's RTP (via SDP files), `amix`es them (`normalize=0`) and pushes to `icecast://user:pass@host:port/mount` (`-c:a libmp3lame`/`-f mp3` or `libopus`/`-f ogg`). A permanent silent stereo **anchor** (`anullsrc`) keeps the Icecast source alive (streaming silence) when there are zero active producers. The Icecast target is supplied by whoever starts streaming (in-call **Streaming** settings panel, persisted in `localStorage`), validated by `icecastConfigSchema`, sent on `start-streaming`, and **never broadcast** — only `streaming-started { by }` / `streaming-stopped` / `streaming-failed` go to the room (state is room-wide, like recording: a `LIVE` badge + `announceEvent`).

Key constraint: a **paused** producer (peer muted) sends no RTP and would stall `amix`, so the mixer is **rebuilt** (debounced, `rebuildDebounceMs`) whenever the _active_ producer set changes — join/leave/share/mute/unmute (`addProducer`/`removeProducer`/`setProducerActive`, wired in `signaling.ts`). Each rebuild kills+respawns the mixer, i.e. a brief Icecast source reconnect; configure an Icecast `<fallback-mount>` for seamless listening. `StreamManager` takes injected `StreamDeps` (reuses recording's structural mediasoup/process interfaces) so it's unit-testable without real ffmpeg/mediasoup.

### In-call audio sources & URL proxy (`server/src/audio-sources.ts`)

The in-call "Stream audio" chooser (`AudioSourceDialog.tsx`) plays into the **same per-stream `<audio>` → file producer** as the local-file path (`startFileSource` in `useMediasoup.ts`), from three sources: a local file (object URL), a **server-side library** file, or a **public URL**.

- **Library**: a browsable **folder tree** under `AUDIO_LIBRARY_DIR` (default `/var/lib/sonicroom/media`). `GET /api/audio-library?path=<subfolder>` lists (`{ path, entries:[{name,dir}] }` — folders first then audio files, dotfiles/symlinks dropped); `GET /api/audio-library/file?path=<relpath>` serves one file. `resolveLibraryPath` is the traversal guard (neutralizes leading slashes/backslashes, collapses `..`, rejects anything escaping the root incl. sibling-prefix), `isAudioFileName` gates the served basename, and `sendFile` is rooted with `dotfiles: deny`. The picker (`AudioSourceDialog`) is a file browser: click a folder to descend, a back button / **Backspace** goes up, names truncate via CSS while the full name stays in each button's `aria-label`.
- **URL proxy**: `GET /api/audio-proxy?url=…` is a same-origin proxy so Web Audio can consume sources lacking CORS headers. It first tries a **direct** pass-through (preserving `Range`/seek for plain audio + Icecast radio), and if the body isn't browser-playable, **transcodes** via the fallback resolvers — ffmpeg for direct media streams (IPTV `.ts`/HLS/DASH/raw, picked by extension _or_ content-type) and yt-dlp for sites (YouTube/SoundCloud/…), each backing the other.
- **SSRF guard** (`resolvePublicAudioUrl`): http(s) only, no credentials, ≤4 KB; rejects any address resolving to private/loopback/link-local/CGNAT/metadata (IPv4 + IPv6 incl. `::ffff:` mapped); the direct fetch **pins DNS** to the validated address (rebinding-proof) and **re-validates every redirect**. Caveat: the **transcode fallback can't be DNS-pinned** — ffmpeg/yt-dlp resolve the host themselves, so a rebind between the Node check and their connect is a residual gap (ffmpeg's `-protocol_whitelist` still blocks `file:`). The three endpoints are **unauthenticated** like the rest of `/api`; the transcode path (which spawns processes) is bounded by a **concurrency cap** — `MAX_CONCURRENT_TRANSCODES` (env `AUDIO_TRANSCODE_LIMIT`, default 32; a slot is held for the whole playback, and only transcoded URLs count — plain audio/radio/library/local don't); over the cap returns **503**. If this is internet-facing, gate/rate-limit it further.

`audio-sources.ts` is split into pure helpers (guards + argv builders) and the process-spawning resolvers, which take an **injected `spawn`** so the first-byte gating, teardown, timeout, routing/backup, and concurrency cap are unit-tested with a fake child process (no real ffmpeg/yt-dlp) — same seam as `RecordingManager`/`StreamManager`.

### Video rooms (audio-first: off unless the room type is "Video call")

SonicRoom stays **audio-first**: a room is a **video room only** when it was created as one — the lobby's **Room type** fieldset (radio group: **Audio call**, always the default, / **Video call**) or **`?video=true`** (also `on`/`yes`/`1`; `off`/`false`/`no`/absent = audio). `isVideoRoomParam` in `client/src/lib/video/room-type.ts` parses it. The flag is **`room.isVideo`** server-side — **sticky** for the room's lifetime (audio → video only, like `isPublic`), set by the `video` join field, returned as **`isVideo`** on the join response, and broadcast as **`room-video`** to peers already inside when a later joiner flips an audio room (they then load the video UI too). A video room **pins the SFU** (`shouldForceSfu`) from its first join, so video never rides the P2P mesh and the first camera on/last camera off never flaps the mode. **The produce handler rejects any `kind: "video"` producer unless `room.isVideo`** (and rejects a kind/source mismatch), so an audio room can never carry video regardless of client.

- **Nothing video loads in an audio room.** The client's only switch is the store's `roomIsVideo` (server truth, never the URL). When it's true the hook dynamically imports `lib/video/video-media.ts` (`VideoMedia`, held in `videoRef`; null in every audio room — all call sites are `videoRef.current?.…`) and `Room.tsx` mounts two `React.lazy` chunks, `components/video/VideoStage.tsx` (the grid) and `VideoControls.tsx` (the toolbar). The Claude SDK and MediaPipe are reached only through dynamic imports inside those and get their own `manualChunks` (`claude-sdk`, `mediapipe`) so they never join the shared `vendor` chunk.
- **Everyone enters with video off.** Camera = a separate **`source: "camera"`** producer (VP8, ≤600 kbps, 640×360 ideal — voice stays the priority; the router now lists `video/VP8` alongside Opus). `start-video`/`stop-video` (`signaling/handlers/video.ts`) only broadcast **`video-started`/`video-stopped`** (announced via `announceEvent` + the new `video-on`/`video-off` cues, and visually as tiles + participant-list indicators) and authoritatively close the camera producer on off. The camera/screen producers are re-produced by `setupSfuInner` (`videoRef.current?.produceAll()`) after a mode rebuild/reconnect, and their tiles drained like audio (`drainPending`). Video producers are **never** fed to the `AudioLevelObserver` or Icecast streaming (`kind === "audio"` guards in `produce` and the streaming start snapshot); **recording does capture them** in a video room — see "Recording a video room" above — and `stop-video` drops the camera's capture the way `stop-share` drops the share's.
- **Screen share = picture only in video rooms.** `startAudioShare` uses the same `getDisplayMedia` call as always; in a video room it keeps the video track and produces it as **`source: "screen"`** (≤1.5 Mbps, 15 fps) next to the audio `share` producer — one share, two producers, both closed by `stop-share` / `stop-peer-stream`. In an **audio room the video track is still discarded** (audio-only share, exactly as before), and extra microphones etc. are untouched — they remain audio-only everywhere. A video-room share with no audio track is allowed (a silent screen share); an audio room still refuses it.
- **Incoming tiles**: `VideoMedia.consume` (routed by `source` in the join snapshot and `new-producer` via `isVideoSource` in the hook) keeps the `MediaStream`s; the store keeps `videoTiles` (by producerId) and sets **`PeerState.hasVideo` / `hasScreen`**, which drive the participant-list indicators (icon + "sharing video"/"sharing screen" in the row's accessible name and the options menu header). `video-stopped` / `share-stopped` / `peer-stream-stopped` / leave / kick all drop the right tiles (`removeOwnedBy`).
- **Stage size — the video FILLS the window** (`components/video/VideoStage.tsx` + the pure `lib/video/stage-layout.ts`). A video room lays `Room`'s `<main>` out as a non-scrolling column: the stage takes `flex-1` of whatever is left after the participant list (capped to `max-h-[30vh]` there via `maxHeightClass`, and self-scrolling), and the grid **measures itself** (`ResizeObserver`) so `bestGrid(count, w, h)` can pick the column count whose tiles come out **biggest in the box actually available** — one camera fills the stage, two sit side by side, four take a quarter each. The old fixed `grid-cols-2/3/4` inside a `max-w-5xl` box drew a one-on-one call as a ~240 px thumbnail marooned in an empty page, which a low-vision user reads as "the video is tiny and there are bands above and below it" (a report that started this). Tiles are `h-full` with **cameras `object-cover`** (filled edge to edge — no letterbox bars; cells come out near 16:9 so the crop is slight) and **screens `object-contain`** (cropping a shared screen loses content). A screen share among other tiles keeps its double-size cell, but only when the chosen grid has the 3 spare cells for it — otherwise the grid is recomputed without the span rather than overflowing into implicit rows. `bestGrid`/`fallbackGrid` are unit-tested.
- **Fullscreen** (`lib/video/fullscreen.ts`): the stage `<section>` itself is the fullscreen element, so the toolbar button inside it is still the way back out; **E** (video rooms only) toggles it and Escape leaves it. `Room` owns the keydown handler but not the element, so the shortcut arrives as a bumped `fullscreenSignal` prop (same shape as Chat's `focusSignal`). State is driven by the browser's own `fullscreenchange` — never optimistically — so both directions are announced from one place with bare `announce()` (a local view choice, like pinning). The helper handles the `webkit` spellings and reports "not available" out loud where element fullscreen doesn't exist at all (iOS Safari) instead of leaving a dead button.
- **Pinning a video** (`pinnedVideo` in the store): one camera or screen fills the stage while everyone else drops to a thumbnail strip. It is a **purely local view choice** — never signaled, so the person you pin is never told — and is offered both from the **participant's menu** ("Pin X's video / screen", "Pin my video"; the option shows an `aria-pressed`-style flipped label like Mute/Unmute) and as a button on each tile. Announced with bare `announce()` (transient and listener-only, like local mute — not a room event, so it does **not** go to chat).
  - **Pinned by `(peerId, source)`, never by producerId.** A camera turned off and back on is a **brand-new producer**, so a producer-keyed pin would silently die on every camera blink; the same is true after a mode rebuild/reconnect (`clearVideoTiles` drops every tile and re-consumes moments later). While the pinned picture is missing the pin is **kept** and the stage just falls back to the even grid, announcing that it is waiting; it fills the screen again by itself when the producer returns. The pin is cleared outright only when that peer **leaves** (`removePeer`, incl. the rejoin's peer reconciliation, which is what clears a pin on someone who reconnected under a new socket id) or we do (`reset`). `setRoom` **re-points** a pin on our OWN camera to the new peer id, since a reconnect rejoins under a new socket id.
  - The pin/unpin option stays offered while the pinned picture is **off** (`peer.hasVideo`/`hasScreen` false) — otherwise a pin on a camera that just went dark would be impossible to remove until they turned it back on.
- **Face-centering guidance** (`lib/video/face-centering.ts` + `face-locator.ts`, loop in `VideoControls`): while **your camera is on** and the toggle (beside the camera button; `videoGuidanceEnabled`, persisted, **default on**) is enabled, a face detector runs as fast as it can (≥120 ms floor) on a hidden `<video>` of your stream; `centeringAdvice` maps the largest face's offset (raw, unmirrored coordinates — a face on the image's right is on the **user's left**, so the hint is "move to your right") to a direction, and **`GuidanceAnnouncer`** throttles: new direction at once, same direction every 3 s, "centered" once on recovery, "face not visible" after a 1.5 s grace then every 6 s — spoken on an **assertive** live region. Detector: native `FaceDetector` when present, else MediaPipe BlazeFace (`@mediapipe/tasks-vision`; wasm served from `/mediapipe/wasm` by the vite plugin in `vite.config.ts`, model committed at `client/public/models/blaze_face_short_range.tflite`). If neither works the toggle is shown disabled with the reason.
- **"Describe … video"** (`lib/video/describe-video.ts`, `VideoMedia.describe`): options in the **participant's menu** — "Describe X's video", "Describe X's screen" (only while that picture is live), and "Describe my video" on your own row — snapshot one frame (≤1024 px JPEG) and ask **Claude (`claude-opus-5`, adaptive thinking, low effort)** for a 2–4 sentence description that transcribes readable text, **in the app's current UI language** (`LOCALE_NAMES[locale]` in the prompt). The user's **Claude API key** lives in this browser's localStorage (`sonicroom:claudeApiKey`, key icon in the video toolbar) and the request goes browser → Claude directly (`dangerouslyAllowBrowser`) — it is never sent to the SonicRoom server. The result is logged via `announceEvent` (so Alt+number re-reads it); failures announce a localized reason.
- **Camera backgrounds** (`lib/video/backgrounds.ts` + `background-fx.ts`, picker in `components/BackgroundPicker.tsx`): replace or blur what's behind you, entirely client-side — the raw capture never leaves the browser, so the SFU, recordings and every peer only ever see the composited picture. **Chosen in the LOBBY**, under the "Video call" radio (the picker only renders for `roomType === "video"`), never in the call window: the choice is read once at `startCamera()`, which means the produced track is settled before the first `produce` and is never swapped mid-call. Choices: **none** (the default — the raw camera track is produced and `background-fx` is never even imported: zero cost), **blur**, one of **six CC0 presets** under `client/public/backgrounds` (see its `CREDITS.md`; each ships a 1280×720 image **and** a 256×144 thumbnail — the picker downloads only the ~41 KB of thumbs, the compositor fetches the one full image actually picked), or the user's **own image**. Persisted as `sonicroom:videoBackground` + `sonicroom:videoBackgroundImage` (`videoBackground` / `videoBackgroundImage` in the store), carried lobby→call like `micDeviceId`, and **normalized on load** — a retired preset id, or a `"custom"` whose image is gone, degrades to `"none"`.
  - **Why it isn't expensive.** We segment at the camera's own 640×360 (`CAMERA_CONSTRAINTS`) and the model runs at 144×256 regardless; the "background blur eats a core" reputation is earned at 720p/1080p. MediaPipe is already loaded in video rooms (the face-centering detector) so this adds **no new dependency and no new chunk** — just a second ~250 KB model. Only the **sender** pays: the SFU forwards and never transcodes. The single per-frame JS pixel loop runs at **mask** resolution (~37k floats); every full-res step is `drawImage` on a hardware-accelerated 2D context. **Never read full-res pixels back into JS** — that is what makes these pipelines slow.
  - **The composite** is three GPU draws: the confidence mask upscaled + feathered into the alpha channel (`copy`), the camera frame kept only where that's opaque (`source-in`), then the background painted underneath (`destination-over`). Blur draws the frame oversized so the kernel can't pull transparent pixels in from past the edges. Driven by **`requestVideoFrameCallback`** (rAF fallback) so we do one composite per real camera frame and none while the tab is hidden; output is `canvas.captureStream(fps)` — **not** `MediaStreamTrackProcessor`, which is Chromium-only and Safari matters here.
  - **Confidence masks, not category masks — this is a correctness constraint, not a preference.** Both selfie segmenters are **single-channel** models (`[1,H,W,1]`, one-entry label map `selfie`), and for single-channel output MediaPipe's `tensors_to_segmentation_calculator` **inverts the usual convention**: it writes `0` for the FOREGROUND and `255` for the background, the opposite way round from every multi-class model. Getting that backwards cuts the person out and sends the **real room** to the whole call. The confidence mask has no such convention — it is `P(selfie)` per pixel, identical on the CPU and WebGL post-processing paths — and it hands us a soft edge for free. `segment()` therefore **refuses** anything but exactly one confidence mask rather than guessing, so swapping in a multi-class model fails loudly instead of inverting.
  - **Failing safe.** Anything that can't be honoured — no `canvas.captureStream`, MediaPipe/WebGL unavailable, the model won't load, the camera never yields a frame — returns `null` from `createCameraBackgroundFx`, and `VideoMedia.applyBackground` falls back to the raw camera **and announces it** (`announce_background_unavailable`). Blur specifically is refused, in the picker and in the compositor, when `ctx.filter` is unsupported (Safari < 17): an ignored filter would silently send the real room, which is a privacy failure rather than a cosmetic one.
  - **`VideoMedia` now keeps two streams**: `rawCameraStream` (the device — only it owns hardware, only `stopCamera`/`teardownAll` stop it) and `cameraStream` (what is produced and previewed — the canvas track when a background is on). Everything downstream reads `cameraStream`, so the self tile, the face-centering loop and "describe my video" all see exactly what the room sees. Because warming the compositor is no longer instant, "camera is on" is owned by `cameraActive` (the raw capture) plus a `starting` flag, and `startCamera` re-checks `rawCameraStream` after the await so a stop **during** warm-up can't resurrect the camera or leak the compositor.
- Shortcuts **V** (camera) and **E** (fullscreen stage) are video-rooms-only; both letters stay free in an audio room. `GET /api/public-rooms` and `/api/rooms/:name` now include `isVideo` so the lobby can flag video rooms.

### Shared notes (NoteLab) (`server/src/notes.ts`)

The in-call **Notes** button / **Alt+N** opens ONE collaborative markdown note per room in a **new tab** (never an iframe) — a [NoteLab](https://notelab.gomsen.com) note (accessible realtime co-editing, no accounts, access _is_ the link). The server is the single source of truth for "does this room have a note yet", so **two people can never create two**: the note is created on first request (`POST ${NOTELAB_URL}/api/notes` → `{ editToken }`, built into an **edit** link `/n/<editToken>` so the whole room can co-write), stored on **`room.notesUrl`**, and reused by everyone for the room's lifetime (it dies with the room — no persistence keyed to room _name_). Concurrent first-presses are serialized (a `WeakMap` of in-flight creations in `notes.ts`), and `getOrCreateRoomNote` returns `created` true only for the caller that actually minted the note, so the `open-notes` handler broadcasts/announces exactly once.

- **Alt means Option on a Mac.** Both Alt shortcuts (Alt+1..0 readback, Alt+N) are matched on the **physical** key (`e.code`) in `Room.tsx`, because with Option held a Mac reports the composed character in `e.key` (Option+N is a dead key). Every user-facing mention of the modifier goes through `altKeyLabel()` (`client/src/lib/keys.ts`, localized `key_alt`/`key_option`) so it reads "Option"/"Opción" on macOS/iPadOS — pass it as `{alt}` to any new message that names the key; the manual carries the same note under "With Alt".
- **Handler** (`signaling/handlers/notes.ts`): `open-notes` returns the URL on the ack (the caller opens the tab as feedback); a fresh creation also broadcasts **`notes-updated { url, by }`** to everyone else so their button flips to "open" and their next Alt+N opens it with no round-trip. The join snapshot carries `notesEnabled` + `notesUrl` so a late joiner into a room that already has a note gets it at once.
- **Client** (`useMediasoup.ts` `openNotes`): opens `notesUrl` synchronously if known; otherwise opens a placeholder tab **inside the user gesture** (popup-blocker-safe) and points it at the note once the ack arrives. The `notes-updated` handler (`room-event-handlers.ts`) syncs the URL and logs it to chat via `announceEvent` (deduped against a URL we already have), following the announcements-go-to-chat rule.
- **Config** (`NOTELAB_URL` in `.env`, operator-only like `NOTY_*`): unset disables the feature entirely — `notesEnabled()` is false, the join response reports `notesEnabled: false`, the client hides the toolbar button, and `open-notes` returns `notes_disabled`. Node's global `fetch` with an 8s `AbortSignal.timeout` so a hung NoteLab can't stall the ack.

### Screen-reader manual (`docs/manual/`)

A long-form manual **for screen-reader users**, in every UI locale — its first job is to say that SonicRoom is an **application, not a document**, so NVDA browse mode / the JAWS virtual cursor / Narrator scan mode / VoiceOver Quick Nav must be off or the single-letter commands (`M`, `A`, `F`, `D`, `R`, `W`, `V`, `E`) never reach the app. It then covers the keyboard model (toolbars are ONE tab stop moved with left/right; listboxes are one tab stop moved with up/down + Enter; Escape/Backspace back out), a walkthrough of the lobby and every part of the room, all shortcuts incl. `Alt+1..0` readback / double-press-to-copy and `Alt+N`, the announcements-go-to-chat rule, and troubleshooting.

- **Source** is `docs/manual/{en,es,fr}.md` (pandoc markdown, YAML title block). **Edit these**, never the HTML.
- **`docs/manual/build.sh`** (`pnpm manual`) renders each to a standalone, self-styled page in **`client/public/manual/<lang>.html`** — so Vite copies them verbatim into `client/dist` and the server/Electron bundle serve them with no route of their own. `--metadata document-css=false` drops pandoc's own stylesheet in favour of `docs/manual/style.html` (light/dark via `prefers-color-scheme`, visible focus rings, bordered tables). The generated HTML is **committed** (and prettier-ignored) so building or deploying the app never needs pandoc installed.
- **Linked from the footer** (`ManualLink` in `Footer.tsx`, inside the shared `FooterLinks` used by both the standalone `Footer` and the room's own footer landmark) at `/manual/<locale>.html`, subscribed to the store's `locale` so it re-points on a language switch. Each page carries a switcher to the other languages and a link back to `/`.
- **Electron caveat**: `setWindowOpenHandler` in `electron_client/src/main.ts` sends `http(s)` `target="_blank"` links to `shell.openExternal`, which cannot open an `app://` URL — so it explicitly **allows** `app://` children (a sandboxed, preload-less window) instead of denying them, otherwise the footer link would be dead in the desktop client.

### Screen-reader announcements (rule: announcements go to chat)

Every room-**event** announcement (recording start/stop, audio-share start/stop, music caster start/stop, mute/unmute, …) must go through the store's `announceEvent()`, which speaks it on the ARIA live region in `Room.tsx` **and** appends it to the chat history as a `kind: "system"` entry — chat is the single timeline of everything announced, readable later via the panel or the Alt+1..0 readback. Peer join/leave keeps its dedicated `kind: "join"/"leave"` entries (localized at render time; `system` entries snapshot the locale active at event time). Bare `announce()` is reserved for re-reading chat content that is already in history: the incoming `chat-message` announcement (which appends a one-time Alt+number hint on the session's first message) and the Alt+number readback itself.

### Public rooms & moderation (knock-to-join, vote-to-kick)

A room is **private by default** and **sticky-public** once any joiner sets it (`isPublic`, via the lobby's "Make this room public" toggle / `?public=true`). Public rooms are listed in the lobby (`getPublicRooms`) and ping the operator's off-box notify daemon on activity (`notify.ts`, target hidden in `.env`). There are **no moderators** — admission and removal are collective:

- **Knock-to-join.** A newcomer to an already-public, occupied room is held in `room.pendingJoins` (keyed by socket id) and gets `{status:"pending"}`; participants see a modal (`JoinRequests.tsx`) + looping knock cue and `join-decision {requestId, allow}`. Allow records an `admittedToken`/`admittedName` (so a reconnect/return skips the gate) and pushes `join-approved`; **deny IP-bans them from this room** (`bannedIps`, checked first on every join) and pushes `join-denied`. Casters and already-admitted sessions skip the gate. The flip private→public broadcasts `room-public` so people already inside update.
- **Vote-to-kick.** Only in public rooms, and only with **3+ votable peers** (humans — non-casters; the target is counted). **`kickThreshold(n)` in `server/src/kick-util.ts` is the single, pure source of truth** (unit-tested): `Infinity` for n<3 (disabled — same as a private room, so no one can be removed unilaterally), else `ceil(n/2)` ("at least half": 3→2, 4→2, 5→3). Votes live in `room.kickVotes` (target peerId → set of voter ids). `vote-kick {targetId, vote}` toggles and broadcasts `kick-vote` to the whole room (incl. the voter — server is authoritative, the client never updates optimistically); `settleKicks` then removes anyone at threshold. **Re-evaluated on every vote AND every membership change** — a leaver shrinks the room and can tip an already-half-voted target over the line. A kick reuses the deny path: room-ban the IP (`bannedIps`), `peer-kicked` to the room + `you-were-kicked` to the target, then `teardownPeer` + force-disconnect (a server-initiated disconnect doesn't auto-reconnect; the client shows a "removed" screen via the `kicked` store flag). `teardownPeer` is the **shared leave/kick path** (the disconnect handler routes through it too); `cleanupKickVotes` drops a departed peer's votes and recounts. Anti-spam: a dedicated `RateLimiter` where **only real toggles cost a slot** (redundant re-vote / empty withdraw is a silent no-op).
- **Client/UI.** Gated on `roomIsPublic && votableCount >= 3` (seeded from the join response + the `room-public` event). The per-peer button (`ParticipantCard.tsx`) uses **`aria-pressed`** for _your_ vote and carries the running tally in its accessible name ("Kick {name} (2 votes)"); the card uses **`aria-selected`** when a peer has any votes against them. Per-vote announcements ("X voted to kick Y" / "…withdrew…") are **bare `announce()`** (transient, like mute); the kick itself goes through **`announceEvent()`** (logged to chat, like recording).

### Moderated rooms ("salas moderadas") — the opt-in third room type WITH admins

Private/public rooms stay moderator-free (above). A **moderated room** is created from the lobby's **"Admin options"** checkbox, which unfolds a **"Participant privileges"** fieldset: one combobox per action (recording, share audio, stream audio = file/URL/library + extra mics, ducking, live streaming, approve joins, chat, notes, mute-one-for-all, mute-all, kick) with `admins` | `everyone` | `nobody` (ducking/approveJoins have no `nobody`; kick adds `admins_vote` / `everyone_vote`), plus "Allow several admins" and "Hide the Powered by link". **`server/src/moderation-util.ts` is the pure source of truth** (zod `moderationPolicySchema` with defaults, `allowed(policy, isAdmin, action)`, `kickMode(policy, isAdmin)`), unit-tested; `client/src/lib/moderation.ts` is its client twin (show/hide only — the server enforces every event regardless).

- **Model.** `room.moderation: ModerationPolicy | null` — **null = today's behaviour, byte-for-byte** (every admin path is gated on it being non-null, so never add an admin capability that isn't). Fixed when the room is **created** (the `moderation` join field is honoured only when `room.peers.size === 0`; a later joiner's is ignored), for the room's lifetime. `room.admins` (peer ids) + `room.adminTokens` (join tokens, so an admin who reconnects under a new socket id gets the role back; `Peer.token` records each peer's). A moderated room **pins the SFU** (`shouldForceSfu`) so the server can pause a muted producer itself.
- **Lobby → room hand-off**: the policy travels via **sessionStorage `sonicroom:moderation:<room>`** (`saveRoomPolicy`/`loadRoomPolicy`; keyed by room so a stale choice can't leak into another room; also lets a host who refreshes while alone re-create the same moderated room), and the last-used policy is kept in localStorage as the fieldset's default. No URL param.
- **Admins.** The creator; co-admins via `set-admin {targetId, admin}` (admins only, naming needs `multipleAdmins`; revoking drops the token). **When the LAST admin leaves while people remain, the room stops being moderated** (`endModerationIfNoAdmins` in `teardownPeer`, run before `applyModeDecision` so the SFU pin is re-evaluated): `room.moderation` → null, `adminTokens` cleared (a returning ex-admin is a regular participant), **`moderation-ended {}`** broadcast → the client nulls `moderation`, empties `adminIds` and logs `announce_moderation_ended` via `announceEvent`; every gate in `Room.tsx` derives from `moderation`, so all controls/chat/PoweredBy come back by themselves. Pending knocks are re-broadcast since everyone may now answer them. Nobody is auto-promoted (that was the earlier design and was ruled out — a reconnecting sole admin therefore ends moderation instantly, since disconnect routes through `teardownPeer` with no grace). Admins can't be vote-kick targets; an admin can be muted/kicked (directly) only by another admin; nobody can target themselves. The join response carries `moderation`, `isAdmin`, `admins`; **`admins-changed { admins, change:{peerId, displayName, isAdmin, reason: named|revoked, by} }`** keeps clients in sync (store `setAdmins` → `PeerState.isAdmin`; announced via `announceEvent`).
- **The door is always knock-gated** in a moderated room, public or not (`gated = wasPublic || room.moderation`); admins (by token) skip it. `approveJoins: "admins"` sends `join-requests` **only to admin sockets** (`broadcastJoinRequests`) and the join snapshot's queue only to peers who `canApproveJoins`; `join-decision` is refused otherwise. The client mounts `JoinRequests` only when allowed.
- **Forced mute is SOFT** (`mute-peer {targetId}` / `mute-all`, handler `signaling/handlers/admin.ts`): the server pauses the target's voice producer(s), flags `peer.muted`, emits `you-were-muted {by}` to them and `peer-muted {peerId, by}` to the rest (`by` makes the client log it as a named room event instead of the transient self-mute line); the person can unmute normally (`producer-resume` isn't gated). `all-muted {by}` is the one room-level log line. The client's `forcedMuteRef` applies the local half without a `producer-pause` emit.
- **Kick.** `kick-peer {targetId}` = direct removal when `kickMode` is `"direct"`, reusing `kickPeer(room, id, "admin", by)` (room-ban + teardown + disconnect; `peer-kicked`/`you-were-kicked` now carry `reason: "admin"` + `by`). Vote modes reuse the collective machinery with **`kickElectorateCount`** (admins only for `admins_vote`, else `votablePeerCount`) feeding the same `kickThreshold` — so "with vote" is still disabled below 3 eligible voters, exactly like a public room.
- **Gates** (`allowed(...)` → `{ ok:false, error:"forbidden" }`): `start/stop-recording`, `start/stop-streaming`, `start-share`, `start-file-stream`, `start-extra-mic`, `set-ducking`, `chat-message`, `open-notes`, and the `produce` handler by source (`share` → shareAudio, `file`/`mic` → streamAudio) so a client can't skip the start-\* events. Mute/kick/set-admin/… are `rate_limited` through the existing `kickLimiter`.
- **Recording download follows the `recording` permission.** The download endpoints are unauthenticated and capability-keyed on the recording id, so "may download" = "was handed the id": `canRecord(room, peerId)` in `room-helpers.ts` nulls `recordingId` for a denied peer in the join snapshot, `recording-started` and `recording-stopped` (each now emitted per peer) — they still get the REC badge and the announcement, just no Download/Tracks buttons (`AudioControls` renders them off `recordingId`). `sendRecordingAccess` emits **`recording-access { recordingId | null }`**: `set-admin` hands an admins-only recording to a newly named admin (client announces `announce_recording_available`) and withdraws it from a revoked one (silently — a file already fetched is theirs), and `endModerationIfNoAdmins` hands it to the room. Same caveat as notes: an id already received can't be revoked at the HTTP layer.
- **Notes** (`notes: admins|everyone|nobody`, default everyone): since a NoteLab link IS the access, the gate covers who is _handed_ the URL, not just the button — `canOpenNotes`/`sendNotesUrl` in `room-helpers.ts`: the join snapshot nulls `notesUrl` for a denied peer, the creator's `notes-updated` goes only to allowed peers, a newly named admin gets it on `set-admin` (`by: null` → the client announces `announce_notes_available` instead of "X opened notes"), and `endModerationIfNoAdmins` hands it to the room. A revoked admin loses the button/Alt+N (which says `announce_not_allowed`) but a link they already opened can't be withdrawn.
- **Role changes are settled server-side on `set-admin`** (`handlers/admin.ts`), never left to the client to infer: with `approveJoins: "admins"` the target gets the current knock queue (empty on revoke, so a stale list from an earlier stint can't linger); admins-only notes are handed over; in a vote-kick mode a new admin's incoming votes are dropped (`dropKickVotesAgainst` → `kick-vote` recount to 0, which also clears each client's own pressed state), a revoked admin's cast votes are dropped under `admins_vote` (`cleanupKickVotes`), and `settleKicks` re-runs since the electorate's threshold moved. Client-side every gate derives from `moderation` + `isAdmin` at render time (`Room.tsx` → `AudioControls`, which also closes the streaming popover when `canLiveStream` drops).
- **Client.** Store: `moderation`, `isAdmin`, `adminIds`, `PeerState.isAdmin`. `Room.tsx` computes the gates once and passes them down: `AudioControls` **does not render** a denied control (and drops it from the toolbar's arrow order) and gains a **"Mute everyone"** button (shortcut **Ctrl+Shift+M**, matched on `e.code === "KeyM"` in `Room.tsx` — a deliberate chord so it can't be hit by accident next to `M`; only in a moderated room, else the browser keeps the combo; a denied peer hears `announce_not_allowed`); shortcuts `A`/`F`/`D`/`R` bare-`announce` `announce_not_allowed` when denied; `Chat` gets `composer: "on" | "off" | "admins-only"` (the panel stays — announcements live there); `ParticipantList` rows carry an admin badge + "administrator" in the accessible name and the options menu adds **Mute for everyone / Make (Remove) administrator / Remove from room**; the header shows a **MOD** badge; `FooterLinks` hides `PoweredBy` when `policy.hidePoweredBy`. The manual has a chapter per language.

### Reserved rooms (host-keyed names) — `server/src/reservations.ts`, the `/admin` UI (`admin.ts`) and `pnpm reserve`

Rooms are ephemeral and created by whoever joins first, so a link advertised ahead of time can be **squatted** (someone opens it early and becomes creator/admin with a policy of their choosing) and a moderated room **evaporates** when it empties or its last admin drops. A **reservation** pins a room name to a host: only a join presenting the reservation's **host key** may OPEN the room (create it from empty); anyone else arriving early is refused with **`reserved`** (no room is created, so the name reads as not live), the client shows a waiting screen (`awaitingHost` in the store, `room_awaiting_host`) and **polls `GET /api/rooms/:name` every 3 s** (`reservedRoomWait.pollMs`, exported so tests can shorten it) until `exists`, then re-joins by itself — landing in the moderated room's knock gate like anyone else. The room's **policy comes from the reservation** (the joiner's lobby fieldset is ignored), `room.reserved` is set, and **`endModerationIfNoAdmins` skips reserved rooms**: it stays moderated with no admin inside, and the key holder is an admin on **every** join (`isHost` folds into `returningAdmin` in the join handler, so they also skip the knock). Anyone holding the host link is the host — there is no per-person identity.

- **Store**: a JSON file, `RESERVATIONS_FILE` (default **`<repo>/data/reservations.json`** — `data/` is gitignored and outside `client/dist`, so it is never served): `{ version: 1, rooms: { <name>: { hostKeyHash, moderation, createdAt, expiresAt|null, note } } }`. `ReservationStore` (what the join handler reads) re-reads it on mtime/size change, so a new reservation needs **no restart**; a malformed/unreadable file logs `[reservations] … reservations are OFF` and disables the feature rather than crashing. Writers (`readReservationsFile`/`writeReservationsFile`: validate, atomic tmp+rename, prune expired) are the admin UI and the CLI. Keys are random 192-bit base64url tokens, so a plain SHA-256 at rest is enough (`verifyHostKey` is constant-time on the digests). Reserving is **operator-only on purpose** (no public endpoint — a name-squatting surface). **Under systemd** (`ProtectSystem=strict`) `data/` is the ONE writable path in the tree — `ReadWritePaths=/home/sonicroom/data`, directory owned by the service user (`sonicroom:sonicroom` 0750). A root-run CLI that creates the file chowns it to the directory's owner (best effort) so the admin UI can still rewrite it.
- **Admin UI** (`GET /admin`, API under `/api/admin/*`, page at `server/src/admin/index.html` — plain accessible HTML, no build): **OFF unless `ADMIN_UI_PASSWORD`** is set in `.env` (then `/admin` is just an unknown SPA route). It is deliberately **not linked from the client**, but the password is the gate, not obscurity: login is constant-time, **rate-limited 5/min per client IP** (left-most `X-Forwarded-For`), and yields an **HttpOnly SameSite=Strict** session cookie (`sonicroom_admin`, random token in memory, 12 h; `Secure` when the request is https directly or via `X-Forwarded-Proto`). Every mutating route also requires the `X-SonicRoom-Admin: 1` header (CSRF belt-and-braces). Pages/API are `no-store` + `noindex`. Routes: `login`/`logout`/`session`, `state` (reservations without hashes + live rooms with `reserved` flag), `POST reservations {name, days, policy, note}` (returns the host link **once**), `POST reservations/:name/rotate`, `DELETE reservations/:name`. Links use `PUBLIC_URL` if set, else the request origin (`requestBaseUrl`). Mounted in `index.ts` **before** `express.static`/the SPA fallback; the vite dev server proxies `/admin` to :3100 like `/api`. HTTP-tested in `admin.test.ts` (real express on an ephemeral port).
- **CLI**: `pnpm reserve <room> [--days N] [--policy <file.json|{json}>] [--note TEXT] [--base-url URL]` prints the **host link** (`/room/<name>?host=<key>` — give to the host only; the key is printed once and never stored) and the **public link**; `--rotate <room>` (new key, same policy — the old link dies), `--remove <room>`, `--list`. Default expiry 30 days (`--days 0` = never). `--base-url` defaults to `PUBLIC_URL` (from `.env`) or `http://localhost:3100`. Same actions as the UI, for the no-browser route.
- **Client**: `Room.tsx` reads `?host=`, stashes it per room in **sessionStorage `sonicroom:hostKey:<room>`** (synchronously, so the redirect to the lobby for a display name keeps it) and **strips it from the URL** with a replace-navigate (merged with the canonical-lowercase rewrite) so a copied address never carries it; `join(..., { hostKey })` sends it as the `hostKey` join field. `leave()` cancels the host-wait poll (`hostWaitRef`) so "back to lobby" from the waiting screen stops it. `/api/rooms/:name` now also returns `reserved` (on both 200 and 404) so a client can tell "wait for the host" from "nobody's here".
- **Tests**: `reservations.test.ts` (pure helpers + the file-backed store with a temp file), `admin.test.ts` (helpers + the router over HTTP: page headers, auth, header check, rate limit, cookie flags, reserve/rotate/remove, logout), `useMediasoup.test.ts` "reserved rooms" (refuse → wait → auto-rejoin; leave cancels the poll; other errors reject at once), `room.test.ts` (`awaitingHost`). The manual has a "Reserved rooms" section per language.

**Room lookup by name.** Alongside the public directory, `GET /api/rooms/:name` (`getRoomInfo` in `room-manager.ts`) answers for **one** room, public **or private** — `200 {exists:true, name, participants, casters, isPublic, mode}` if it's live, `404 {exists:false, name, error}` if not, `400` if the name fails `roomNameSchema`. Since a room only exists while it holds ≥1 peer, a 404 means "nobody is in a room by that name", **not** "that name is free"; and a 200 is not an invitation (joining still runs the knock gate / `bannedIps`). It answers for private rooms too, so it does leak "is anyone in `<name>` right now" to anyone who guesses the name — only the **count** is exposed, never participant names (those stay in `getPublicRooms`, public rooms only). Unauthenticated like the rest of `/api`; gate it if that matters for your deployment.

### Client routing

Two routes (`client/src/main.tsx`): `/` → `Lobby`, `/room/:roomName` → `Room` (a bare `/<name>` redirects to `/room/<name>`). **Room names are case-insensitive**: lowercase is the canonical form — `roomNameSchema` (server) lowercases on parse so the room map is keyed consistently, the lobby's `sanitize` lowercases, and `Room.tsx` lowercases the URL param and `replace`-navigates a mixed-case link to its canonical URL (so `/room/Foo` and `/room/foo` are one room and share the same per-room storage keys). Room URL params: `?p2p=off` (also false/0/no/disable/disabled) pins SFU; `?public=true` (also 1/yes/on/enable/enabled/public) lists the room publicly; `?video=on` (also true/yes/1; off/false/no/absent = audio) makes it a **video room** (see "Video rooms"); `?displayName=…` deep-links past the lobby name prompt; `?lang=` overrides the UI language (see i18n below); `?ios=on` (also 1/true/yes/on/enable/enabled/force/ios) forces the **iOS audio path** on any browser — `isIOS` in `client/src/lib/microphone.ts` is `iosForcedByUrl || <UA detection>`, so the mic constraints and the shared `AudioContext` drop the 48 kHz sample-rate pin and voice processing defaults on. Read **at module load** (the `AudioContext` is constructed on import), so it only takes effect on a page load carrying the param — the lobby forwards it into the room URL it navigates to. State lives in a single zustand store (`client/src/stores/room.ts`); mic gain persists to localStorage. The room name is reflected into `document.title` from the `Room` component.

### Lobby: creating vs joining (`client/src/lib/room-lookup.ts`, `Lobby.tsx`)

The lobby form **reshapes around the room name**: someone JOINING a live room sees only what is theirs to change (display name, mic test, "join without a microphone", the video background if the room is a video room, the public list, Join) — the **room options** (Room type, Disable P2P, Make public, Admin options) belong to whoever **creates** the room. The lobby asks `GET /api/rooms/:name` (`fetchRoomStatus`) **400 ms after typing stops**, at once for a linked room (`/?room=…`), and **re-polls every 5 s** (`roomLookupTiming`, exported so tests shorten it) since a room can open or empty under the visitor. The pure `lobbyMode(status, hasHostKey)` → `create | join | reserved-wait | reserved-host` and `showsRoomOptions(mode)` are the source of truth, unit-tested.

- **Hidden means NOT SENT.** `disableP2p` / `isPublic` / `video` are all **sticky server-side for ANY joiner**, so `handleJoin` drops them (and saves a `null` moderation policy) whenever the options weren't on screen — otherwise a leftover tick would flip someone else's room public/video. A lookup still in flight for a just-typed name counts as "create" (the options were visible when Enter was pressed). URL params on a direct `/room/<name>?…` link are untouched.
- **Announced, and explained on screen.** `applyStatus` announces on the lobby's live region (`#lobby-announcer`) **only when what's on screen changes** (`lobby_room_exists_announce` + `lobby_room_options_hidden`, or `lobby_room_new_announce` + `lobby_room_options_shown`), plus the first answer for a linked room (nothing was hidden, so just "you'll be joining it"). The visible twin is a note under the room field, wired as its `aria-describedby`. Picking from the public list seeds the status immediately and folds "hiding the room options" into the "room selected" announcement.
- **No yanking.** The last answer stays up while the next lookup is in flight (`status.name` says which name it's for) so the form doesn't flicker per keystroke; a linked room holds the options **back** until the first answer instead of showing and then removing them; a failed lookup keeps what was known about that name (else falls back to the full form); and if a control being hidden holds focus (`[data-room-options]` / `[data-admin-options]`), focus moves to the display-name field instead of dropping to `<body>`.
- **Reserved, not yet open**: without the host key → `reserved-wait` (everything hidden, "you'll wait for the host"); with it (`sonicroom:hostKey:<room>`) → `reserved-host`: room options shown but **not Admin options** — the policy comes from the reservation.
- **Tests**: `room-lookup.test.ts` (pure) and `components/Lobby.test.ts` — the real component under `MemoryRouter` (written with `createElement`, since vitest only includes `*.test.ts`): show/hide + exact announcements, focus rescue, linked-room hold-back, the background picker for a live video room, what the navigate URL carries, reserved rooms.

### Localization / i18n (Paraglide JS)

UI strings live in `client/messages/{en,es,fr}.json` (flat key→string, `{var}` interpolation). The **inlang Vite plugin** (`paraglideVitePlugin` in `vite.config.ts`) compiles them into tree-shakeable, type-safe functions under `client/src/paraglide/` — **generated, gitignored, never hand-edit** (regenerated on every `pnpm dev`/`pnpm build`; or `pnpm --filter client exec paraglide-js compile --project ./project.inlang --outdir ./src/paraglide`). `tsconfig` has `allowJs` on so `tsc` reads the JSDoc-typed output. Import message functions from `../paraglide/messages.js` (`m.some_key(...)` or named exports) and call them at render/event time — they read the active locale, so they work in non-React code too.

- **Locale resolution** (`strategy` in `vite.config.ts`, first hit wins): `localStorage` (the picker's choice) → `preferredLanguage` (browser) → `baseLocale` (`en`). On top of that, a **`?lang=` override** is applied imperatively in `client/src/lib/i18n.ts` _before_ anything reads the locale (so the store/`main.tsx` import `i18n` to force that ordering), then persisted.
- **Switch without reload**: the locale is mirrored in the store (`locale` + `setLanguage`, which calls Paraglide's `setLocale(…, { reload: false })`). `<App>` in `main.tsx` subscribes to `locale` so a change re-renders the whole tree **in place** — every `m.*()` re-evaluates, but nothing remounts, so an active call survives a mid-session language switch. `setLanguage` also updates `<html lang>`.
- Non-component strings are localized via the same functions: SR announcements in `useMediasoup.ts`, and `client/src/lib/chat.ts` (`formatMessage` stays the single source for both the visible message and its ARIA announcement; `relativeTime` builds a per-locale `Intl.RelativeTimeFormat`).
- **Add a language**: add the code to `locales` in `client/project.inlang/settings.json`, add `messages/<code>.json` (keys at parity with `en.json`), and add its native name to `LOCALE_NAMES` in `client/src/lib/i18n.ts`. The picker (`LanguageSelect`) and detection pick it up automatically.

## Deployment / runtime

- Runs under systemd as **`sonicroom.service`** (`ExecStart=/usr/bin/pnpm start`, `WorkingDirectory=/home/sonicroom`). The **sample unit in the repo root deliberately carries no `Environment=` lines** — all config lives in the gitignored `.env` so there's one place to edit and nothing deployment-specific is committed (a real env var still wins over `.env`, which is why this box's `/etc/systemd/system/sonicroom.service` can keep setting them). Env (loaded from `.env` by `server/src/load-env.ts`, which **must stay the first import** in `index.ts` — ESM evaluates imports before the importing module's body, so anything read at module scope, e.g. `transportOptions`, would otherwise miss the file): `PORT` (3100), `MEDIASOUP_WORKERS` (optional — how many mediasoup workers to spawn; unset = one per core as always, pure `resolveWorkerCount` in `mediasoup-config.ts`, unit-tested, ignores junk/<1 with a warning and caps at 64), `ANNOUNCED_IP` / `ANNOUNCED_IP6` (addresses announced to ICE — required in production; **each accepts a comma/space-separated LIST**, one `listenInfo`/ICE candidate per address, built by the pure `buildListenInfos` in `mediasoup-config.ts` and unit-tested. A host behind NAT announces public **and** LAN address — consumer routers rarely hairpin, so LAN peers can't reach the public IP — and `ANNOUNCE_LOCAL_IPS=true` appends the host's own non-loopback, non-link-local interface addresses instead of hardcoding a DHCP one. Cost: one extra UDP port per transport per address out of the 101-port range, ×2 transports per peer. The startup log prints what was announced, or warns when nothing is), `NODE_ENV=production`, optional `INSTANCE_NAME` (rebrands the app title — injected into the served `index.html` at runtime, read client-side via `getInstanceName()` in `client/src/lib/branding.ts`, so no rebuild), optional `TURN_CREDENTIAL_URL` (the ephemeral-TURN minter clients ask; injected the same way — see below). Restart with `systemctl restart sonicroom`. **`.env` must be readable by the service user** (`User=sonicroom` in the unit; keep it `root:sonicroom` 0640) — a root-only `.env` makes `loadEnvFile` fail with EACCES and every `.env`-gated feature silently turns off (Notes button gone, caster joins rejected, no noty pings, library dir back to default); `load-env.ts` now logs an `[env]` warning at startup when that happens.
- **Client changes need only `pnpm build`** — `express.static(client/dist)` serves the new bundle on the next page load, so no server restart and no dropped calls. **Restart the service only for server-code changes** (server runs TS live via tsx).
- Ports: WebRTC media UDP **40000–40100**; recording RTP **50000–50998**; Icecast-streaming RTP **51000–51998**. (The recording/streaming RTP ranges are loopback-only — mediasoup→ffmpeg on 127.0.0.1 — so no firewall change; only the outbound Icecast connection leaves the box.) ICE is **UDP-only** by design; TCP/TLS fallback is handled by an external coturn (`turn.gomsen.com`). **TURN credentials are never baked into the bundle.** That coturn runs with `use-auth-secret` (the TURN REST API), so the long-lived secret stays server-side (`/etc/turnauth.env`, `/etc/turnserver.conf`) and `turnauth.service` mints a short-lived credential — username `<expiry>:<label>`, credential `base64(HMAC-SHA1(secret, username))` — from `https://turn.gomsen.com/ice`. That minter endpoint is **operator-configurable**: `TURN_CREDENTIAL_URL` in `.env` is injected into the served `index.html` alongside `INSTANCE_NAME` (so pointing an instance at its own minter is a restart, not a rebuild) and read client-side by `turnCredentialUrl()`, which falls back to `DEFAULT_TURN_CREDENTIAL_URL` when unset. `iceServers()` in `client/src/lib/runtime-config.ts` is therefore **async**: it returns an injected Electron override if present, else the minted list (cached until just before expiry), else STUN-only if the minter is unreachable (direct P2P still works; only the relay fallback is lost). The same minter serves the games, FileDrop, GameRoom and Ecobox, so rotating the relay credential is a server-only change.
- **Outbound egress**: besides the Icecast push, the `/api/audio-proxy` URL streamer makes the server fetch arbitrary **public** http(s) hosts (and run yt-dlp, which hits site CDNs) — the SSRF guard blocks private targets but egress to the public internet is the feature. The shared-notes feature also POSTs to the configured `NOTELAB_URL` on first use per room. Keep `ffmpeg`/`yt-dlp` installed and yt-dlp current (see top of this file). Optional env: `AUDIO_LIBRARY_DIR`, `FFMPEG_PATH`, `YTDLP_PATH`, `AUDIO_TRANSCODE_LIMIT`, `NOTELAB_URL`.
